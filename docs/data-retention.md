# 数据保留与墓碑压缩规划

## 当前实现（v0.7）

设置页已经加入“数据健康”面板，实时展示有效任务、专注、复盘、睡眠、墓碑数量、墓碑年龄、近似 JSON 体积、浏览器空间、最近备份和最近 WebDAV 同步时间。

删除墓碑会随任务和专注记录数量增长，但它是多设备同步中传播“这条记录已删除”的依据。现在直接物理删除，会让长时间未上线的设备在下次安全合并时把旧记录重新带回来，因此应用明确禁止自动物理清理。

## 已有保护

- 云端活动文件每次覆盖前都会生成带时间后缀的历史版本，默认保留最近 50 份。
- 客户端同步先展示逐项差异；两端独有记录自动合并，同一记录内容不同必须选择。
- JSON 导出仍包含墓碑，可用于完整恢复和同步诊断。

## 长期压缩策略

采用“同步水位 + 宽限期”后再压缩：

1. 为每台设备生成稳定设备 ID，并在云端同步元数据中记录最后确认时间。
2. 墓碑至少保留 90 天；只有所有已登记设备都确认见过该墓碑后，才进入可清理集合。
3. 清理前生成一份不可变云端历史版本，并允许下载本机 JSON 备份。
4. 设置中的“数据健康”面板持续展示活动记录、墓碑数量、预计占用和进入 90 天观察区的数量。
5. 设备超过 180 天未同步时标记为过期；用户必须明确移除该设备，才允许跨过它的同步水位。

在设备登记和同步水位完成前，墓碑只统计、不物理删除。面板中的“90 天以上”表示进入观察区，不代表现在可以安全删除。这会增加少量存储，但比数据复活或永久丢失更安全。

## 触发阈值

- 少于 100 条墓碑且墓碑占全部记录不足 25%：显示为健康，无需处理。
- 达到 100 条墓碑或占比达到 25%：显示为“留意增长”，但仍不会自动删除。
- 墓碑超过 90 天：进入观察区，等待未来的设备同步水位确认。

这套阈值只决定提示级别，不会改变或删除用户数据。
